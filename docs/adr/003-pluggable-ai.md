# 003. Pluggable AI Provider System

**Статус:** accepted
**Дата:** 2026-04-15

## Контекст

Проект использует несколько AI-моделей для разных задач (классификация текста, генерация изображений, генерация видео). Рынок AI быстро меняется — сегодня лучший провайдер может стать устаревшим завтра. Нужна возможность подключать и менять AI-провайдеров без рефакторинга ядра системы.

## Решение

**Adapter Pattern + Provider Registry.**

Архитектура:
1. **Базовые интерфейсы** (`BaseAIProvider`, `TextAIProvider`, `ImageAIProvider`, `VideoAIProvider`) определяют контракт
2. **Конкретные провайдеры** (`GeminiFlashProvider`, `NanoBananaProvider`, `KlingProvider`) реализуют интерфейсы
3. **Registry** (`AIProviderRegistry`) — единая точка доступа с поддержкой fallback
4. **Tenant config** — каждый тенант может настроить предпочитаемого провайдера per capability

Добавление нового провайдера: 1 файл + регистрация в registry.

## Альтернативы

| Вариант | Причина отказа |
|---------|---------------|
| Прямые вызовы API | Жёсткая связь, невозможно заменить провайдера |
| LangChain | Overkill для наших задач, лишняя абстракция |
| Strategy Pattern (без registry) | Нет centralized management и fallback |

## Последствия

**Плюсы:**
- Добавление провайдера = 1 файл, 0 рефакторинга
- Automatic fallback при сбое провайдера
- A/B тестирование разных AI на одних данных
- Каждый тенант может иметь свои настройки

**Минусы:**
- Чуть больше boilerplate при создании первых провайдеров
- Нужно поддерживать совместимость интерфейсов при эволюции capabilities
