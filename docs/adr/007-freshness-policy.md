# 007. Жёсткая политика свежести материалов в автопилоте

**Статус:** accepted
**Дата:** 2026-05-12
**Заменяет частично:** ADR-006 (раздел про soft freshness floor)

## Контекст

После выкатки multi-format автопилота (ADR-006) обнаружилось, что в очередь публикации регулярно попадают **материалы 2-недельной давности**, хотя свежий парсинг работает каждые 2 часа. Анализ показал четыре механизма, работающих друг против друга:

1. **`freshness floor = 5.0`** в `_compute_freshness` — материалы просроченные по TTL получали искусственный балл 5/10 «чтобы очередь не голодала». Это решение из коммита `2d34e01` оказалось хуже болезни: топ-рейтинговые старые материалы (rel≥8, hype≥7) проходили threshold 7.0 даже при просрочке.
2. **Щедрые `DEFAULT_TTL`** — для `tech / environment / culture / opinion / lifestyle` TTL был 168 часов (неделя). В сочетании с floor=5.0 материалы возраста 2–3 недели считались публикабельными.
3. **Lazy-adapt без учёта свежести** — функция искала «самые рейтинговые ещё не адаптированные» материалы, сортируя по `(relevance + hype) DESC`. Дата материала не учитывалась — старые highly-scored статьи регенерировали адаптации и попадали в драфт-пул.
4. **Бесконечно растущий пул драфтов** — `ChannelAdaptation.status='draft'` никогда не архивировался. На момент диагностики накопилось 454 черновика, многие — старше двух недель. `rank_and_queue` отбирал их наравне со свежими.

Дополнительно: семантический дедуп срабатывал только при `similarity > 0.8` (uniqueness < 2.0). Это слишком строго — два пересказа одной новости из разных источников (≈60-70% совпадение фактов) проходили как уникальные.

## Решение

**Многоуровневый барьер свежести вместо мягкого штрафа.**

### 1. Hard cutoff по возрасту в `rank_and_queue` и `lazy_adapt`
Новое поле `autopilot_config.max_material_age_hours` (default **24h**, override per-channel). Запрос драфтов и поиск материалов для lazy-adapt теперь содержит `JOIN raw_materials ... WHERE scraped_at >= now() - max_material_age_hours`. **Просроченные материалы физически не могут попасть в очередь, независимо от скоров.**

### 2. Удаление `freshness floor = 5.0`
Если категорийный TTL превышен — freshness становится 0, и материал естественно не проходит threshold 7.0. Голодание очереди — это сигнал «нет свежего хорошего контента», а не повод публиковать старое.

### 3. Новая периодическая задача `autopilot_archive_stale_drafts`
Раз в час (`crontab(minute=30)`): черновики, чей материал старше 48 часов, переводятся в `status='archived'`. 48h = 2× от дефолтного cutoff, оставляя слабину для драфтов, которые могли бы попасть в окно.

### 4. Ослабление порога семантического дедупа
`uniqueness < 2.0` (similarity > 0.8) → `uniqueness < 4.0` (similarity > 0.6). Теперь два пересказа одного события из разных источников считаются дублём, и второй пропускается на стадии ранжирования.

## Альтернативы

| Вариант | Причина отказа |
|---------|---------------|
| **Оставить мягкий floor, только понизить с 5.0 до 2.0** | Не решает корень — старые материалы по-прежнему могут пройти при высоком rel/hype. Полумера. |
| **Batch-based selection** (брать только материалы из последнего парсинг-батча) | Слишком хрупко: если в текущем 2-часовом окне ничего не классифицировалось, очередь пустая. Hard cutoff с 24h-окном — компромисс между свежестью и стабильностью. |
| **Two-tier strategy** (отдельные пулы свежих/средних) | Усложнение без явного выигрыша. Один cutoff достаточно. |
| **Удалять, а не архивировать драфты** | Архивация сохраняет историю для аудита/аналитики. Стоимость хранения копеечная. |

## Последствия

**Плюсы:**
- Материалы старше 24h **гарантированно не попадают** в очередь публикации
- 454 застрявших драфта одной job-ой ушли в archived (свободный пул для свежего)
- Hourly archival предотвращает повторное накопление мусора
- Полу-дубли из разных источников теперь отсеиваются
- Каждый канал может крутить ручку `max_material_age_hours` под свою нишу (для вечнозелёных тем поднять, для горячих — опустить)

**Минусы:**
- При редком парсинге (или массовом простое классификатора) очередь может оказаться пустой — это **намеренное** поведение, не баг
- Архивация необратима (статусом). Если нужно «оживить» драфт — придётся менять статус вручную
- Изменение порога дедупа (0.8→0.6) может ложно резать уникальные материалы, схожие по теме. Если ложноположительных будет много — поднимем обратно или сделаем настраиваемым.
- `max_material_age_hours` хранится в `autopilot_config` JSONB, без миграции — старые каналы без явной настройки получат дефолт 24h при следующем чтении

## Метрики для отслеживания

- Доля `autopilot_queue.skip_reason = "material_already_published_*"` — должна снизиться (был эффект «повторов»)
- Среднее `now() - scraped_at` для свежепосчастливленных queue items — должно сжаться к ≤24h
- Среднее число `ChannelAdaptation` со `status='draft'` — должно держаться < 100 после стабилизации (вместо 454+)
- Случаи «пустая очередь N часов подряд» — если станут регулярными, поднять `max_material_age_hours` или ослабить threshold
