# 006. Ratio-balanced мульти-форматный автопилот

**Статус:** accepted
**Дата:** 2026-05-11

## Контекст

До этого решения автопилот для каждого канала отбирал черновики **только одного primary-формата** — `short_post` для Telegram, `longread` для Website, `video_script` для YouTube. На практике это привело к двум проблемам:

1. **Однообразный фид.** Telegram-канал получал только средне-длинные посты на 300–700 символов. Короткие новости (цена, назначение, награда) растягивались до того же объёма «потому что формат». Лента читалась как простыня.
2. **Затраты на обложки.** Каждый пост требовал AI-обложку, что увеличивало стоимость и задержку публикации даже для одно-фактовых новостей, где картинка не нужна.

## Решение

Перейти от **primary-format-only** к **ratio-balanced multi-format queuing**:

1. **Новый формат `flash`** — короткие посты 80–200 символов без заголовка и без обложки, с отключённым превью ссылок.
2. **AI рекомендует формат** при классификации: новое поле `suggested_format` в схеме классификатора (`flash` / `short_post` / `longread`). При адаптации используется AI-рекомендация, если она входит в `channel.content_formats`; иначе — платформенный дефолт.
3. **Балансировка очереди по ratio.** В `autopilot_config` появилось поле `format_ratios` (default `{flash: 0.40, short_post: 0.40, longread: 0.20}`). При постановке в очередь `autopilot_rank_and_queue` пропускает элемент, если его текущая доля за день превышает целевой коэффициент в **1.5×**. Express-стратегия игнорирует баланс (breaking news публикуется немедленно).
4. **Жёсткий дневной лимит лонгридов** (`longread_max_per_day`, default 2). Лонгриды дороже в подготовке и медленнее читаются — лимит защищает от перекоса.
5. **Flash bypass'ит cover-pipeline.** `_get_cover_image`, `_send_with_photo`, генерация обложек — всё пропускается для `flash`. Сообщение уходит чистым текстом с `disable_web_page_preview=true`.

Пересмотрены лимиты длины существующих форматов: `short_post` 300–700 → **250–500**, `longread` 1000–3000 → **1000–2500** — чтобы они не «съедали» нишу друг друга.

## Альтернативы

| Вариант | Причина отказа |
|---------|---------------|
| **Приоритет формата вместо квот** (сначала flash, потом short_post, потом longread) | Не даёт стабильного микса в течение дня — все слоты с утра уйдут под flash, к вечеру останутся только лонгриды. |
| **Случайный выбор формата с весами** | Дисперсия слишком высокая — на 10 постов в день можно реально получить 8 лонгридов подряд. Детерминированная балансировка с допуском 1.5× — компромисс. |
| **Отдельная очередь на каждый формат** | Усложнение модели (3× `AutopilotQueueItem`-таблиц или дискриминатор), без понятного выигрыша. Одна очередь с балансировкой проще. |
| **AI решает не формат, а кол-во символов** | Слишком много свободы — формат это не только длина, но и наличие/отсутствие заголовка, обложки, превью. Жёсткие пресеты надёжнее. |

## Последствия

**Плюсы:**
- Разнообразный фид: ~40% коротких молний, ~40% стандартных постов, ~20% аналитики
- Снижение стоимости: flash-посты не тратят кредиты на генерацию обложек
- Скорость публикации flash повышена (нет ожидания cover_status = ready)
- Express-стратегия для breaking-news по-прежнему обходит балансировку

**Минусы:**
- Появилось ещё одно правило в `autopilot_rank_and_queue` — функция и так была длинной (1043 строки)
- `format_ratios` per-channel — пользователь должен задать осмысленные значения, иначе работает дефолт 40/40/20, который может не подходить под нишу канала
- Нужна data-миграция (`scripts/add_flash_format.py`) для добавления `flash` в `content_formats` существующих TG-каналов — забыть запустить = новый формат не появится в очереди
- Old materials, классифицированные до выкатки, не имеют `suggested_format` — для них используется платформенный дефолт (т. е. они НИКОГДА не станут flash, пока не перекласси­фицируются)
